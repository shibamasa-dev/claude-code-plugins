# diagram

[English](README.md) | 日本語

図をコードで描くスキル。

## 導入

```text
/plugin marketplace add shibamasa-dev/claude-code-plugins
/plugin install diagram@shibamasa-plugins
```

## スキル

| スキル | 使いどころ |
|---|---|
| `one-page-diagram` | 一枚の説明図をインライン SVG か HTML で描く。全体の構成、組織図、業務の概念図など。全部の要素に種別を1つずつ付け（1枚で最大4種）、同じ種別のものだけを横に並べ、矢印の意味を1つに決め、描かなかった観点をキャプションに書く。名前のあるサービスには公式ロゴを、種別には概念アイコンを1つずつ使う |
| `typed-diagram` | 記法が枠の意味を決めている図を描く。フロー図・スイムレーン・シーケンス図・状態遷移図・ER 図・コンポーネント図・C4。リポジトリで管理する Markdown には Mermaid、提案書・客先向けレポート・スライド・共有ページには手で描いた SVG（HTML）、頼まれたら PlantUML か draw.io。読み手の問いから図の種類を選び、全部の枠を宣言した1つの意味に照らして確かめ、種類が混ざるなら図を2枚に分ける |

どちらを使うかは1つの問いで決まる。「枠と矢印の意味を、既存の記法が決めてくれるか」。決めてくれるなら `typed-diagram`、くれないなら `one-page-diagram`。

返信や文書が同じ SVG の図について論点を2つ以上述べるときは、どちらのスキルも `scripts/stepper/stepper.mjs` でその1枚の図の上を順に案内できる。「戻る／次へ」で強調だけが動き（今の論点の要素は枠が太くなり、ほかは薄くなり、札を付けることもできる）、配置と色は描いたまま変わらない。論点の一覧は JavaScript が動かなくても読め、スキルは返信の本文にも論点を全部書く。HTML を表示できない場所では、1枚の図に論点の番号を振る。

どちらも、描いた図をライトとダークで表示して確かめてから渡す。確かめられなかったときはそう伝える。

## 設定

設定もフックも無い。プラグインのデータディレクトリには何も置かない。

### ファイルの置き場

| 何か | 置き場 |
|---|---|
| 図 | 指定したパス。無ければ、その図が説明する文書の中か隣。文書も無ければ作業ディレクトリの `diagrams/<slug>.html`（Mermaid は `.mmd`）。会話の中ではその場に表示する |
| stepper の指定、HTML の断片、ライトとダークの確認用ページ | セッションの scratchpad。断片はその場に表示するか、図の HTML ファイルに入れる |
| ダウンロードしたアイコンと、描画を確かめるために作ったファイル | セッションの scratchpad。無ければシステムの一時ディレクトリ |

## 制限

- ロゴと概念アイコンは描くときにダウンロードする（svgl・Devicon・gilbarbara/logos・Lucide）。そのためネットワークが要る。つながらないときは文字のラベルで描き、そう伝える。できあがったファイルはアイコンを埋め込むので、表示にネットワークは要らない
- Markdown に画像として貼った SVG は、埋め込み先のページが宣言した配色（宣言が無ければ OS のテーマ）でライトかダークを選ぶ。ページの見た目のテーマとずれることがある
- stepper は、`#` の後に16進の文字が3つ以上続く図を断る。色の値と見分けられないため。`url(#ab1-arrow)` のような id の参照も当たるので、id は色に見えない名前にする
- Mermaid の C4 図は実験的な機能。GitHub で見せる図では、C4 の記法を指定されない限り、C4 の1階層をフロー図として描く

## 前提

- 図を表示して見る手段。Claude クライアントのプレビューか、ヘッドレスでスクリーンショットを撮る Chrome
- stepper とテストには Node.js 20 以降（Node.js 24 で確認）
- 任意: Node.js。`@mermaid-js/mermaid-cli` で Mermaid を描画する

## テスト

```bash
bash plugins/diagram/tests/run-all.sh   # stepper の検査と出力。Node.js が要る
```
